# SafeMine: Data Architecture, API Contracts & Database Schema

---

## 1. Data Ingestion Architecture & Data Pipeline

SafeMine processes high-velocity industrial time-series data generated by subterranean physical sensors and infrastructure repeaters.

```
+---------------------------------------------------------------------------------------------------+
| DATA TRANSFORMATION PIPELINE                                                                      |
+---------------------------------------------------------------------------------------------------+
| 1. Physical Sensing (Analog Voltage / I2C Bus Register)                                           |
|       |                                                                                           |
|       v                                                                                           |
| 2. Edge Sampling & ADC Normalization (12-bit ADC: 0..4095 -> CH4 %; LSB/g: ax/16384 -> g)       |
|       |                                                                                           |
|       v                                                                                           |
| 3. Network Transport (JSON Payload via HTTP POST or MQTT QoS 0)                                   |
|       |                                                                                           |
|       v                                                                                           |
| 4. Server Ingestion & Field Normalization (Handle aliased keys: mq4/ch4/gas_ch4)                 |
|       |                                                                                           |
|       v                                                                                           |
| 5. Range Validation & Outlier Clamping (Reject impossible physical values; log sensor faults)     |
|       |                                                                                           |
|       v                                                                                           |
| 6. Mathematical Enrichments (O2 Calculation Engine + Multi-Criteria Risk Scoring)                 |
|       |                                                                                           |
|       v                                                                                           |
| 7. Relational Persistence & Disk Flush (workers state update + telemetry time-series insert)      |
|       |                                                                                           |
|       v                                                                                           |
| 8. Client WebSocket Distribution (Zero-latency broadcast to browser clients)                      |
+---------------------------------------------------------------------------------------------------+
```

## 2. Inbound Sensor Data Schemas

### A. Primary Smart Helmet Payload (`POST /api/telemetry` or MQTT `mineguard/helmet/:id`)

```json
{
  "worker_id": "MNR-001",
  "dht_status": "ok",
  "mq2_status": "ok",
  "mpu_status": "ok",
  "bmp_status": "ok",
  "device_status": "connected",
  "timestamp": 1711234567890,
  "temp": 26.5,
  "humidity": 55.2,
  "ch4": 0.12,
  "gas_raw": 320,
  "o2": 20.65,
  "o2_label": "SAFE",
  "pressure": 1013.25,
  "motion": 1,
  "fall": 0,
  "panic": 0,
  "rssi": -72,
  "battery": 88
}
```

#### Field Specifications & Physical Units:
| Field | Data Type | Physical Units | Operational Bounds | Source Sensor |
| :--- | :--- | :--- | :--- | :--- |
| `worker_id` | String | Identifier | Alphanumeric (e.g. `MNR-001`) | Hardcoded in firmware |
| `temp` | Float | Degrees Celsius ($^\circ\text{C}$) | $-20.0\text{ to }80.0^\circ\text{C}$ | DHT11 NTC Thermistor |
| `humidity` | Float | Relative Humidity ($\%\text{ RH}$) | $0.0\text{ to }100.0\%$ | DHT11 Capacitive Substrate |
| `ch4` | Float | Gas Volume ($\%$) | $0.0\text{ to }5.0\%$ | MQ-2 / ADC conversion |
| `gas_raw` | Integer | Raw ADC Counts | $0\text{ to }4095$ ($12\text{-bit}$) | ESP32 GPIO 34 (ADC1_CH6) |
| `o2` | Float | Atmospheric Oxygen ($\%$) | $15.0\text{ to }21.0\%$ | `o2Calculation.js` / Firmware |
| `o2_label` | String | Safety Label | `SAFE`, `WARNING`, `DANGER` | Threshold evaluator |
| `pressure` | Float | Barometric Pressure ($\text{hPa}$) | $300.0\text{ to }1100.0\text{ hPa}$ | BMP180 Piezoresistive Diaphragm |
| `motion` | Integer | Binary Flag ($0\text{ or }1$) | $1 = \text{motion}, 0 = \text{stationary}$ | MPU-6050 Acceleration Delta |
| `fall` | Integer | Binary Flag ($0\text{ or }1$) | $1 = \text{fall asserted}$ | MPU-6050 Shock + Tilt + Inaction |
| `panic` | Integer | Binary Flag ($0\text{ or }1$) | $1 = \text{button pressed}$ | Helmet Emergency Pushbutton |
| `battery` | Float | Charge Percentage ($\%$) | $0.0\text{ to }100.0\%$ | Battery Fuel Gauge / ADC Divider |
| `rssi` | Integer | Decibel-Milliwatts ($\text{dBm}$) | $-110\text{ to }-30\text{ dBm}$ | Wi-Fi / LoRa Gateway Radio |

## 3. Database Architecture & Relational Schema (`mineguard.db`)

SafeMine uses a relational SQLite schema executed in memory via `sql.js` (WebAssembly) and persisted to disk.

```
+---------------------------------------------------------------------------------------------------+
|                                   DATABASE RELATIONAL SCHEMA MAP                                  |
+---------------------------------------------------------------------------------------------------+
|                                                                                                   |
|  +--------------------+             +--------------------+             +--------------------+     |
|  |      workers       | 1         * |     telemetry      |             |      anchors       |     |
|  +--------------------+ <---------- +--------------------+             +--------------------+     |
|  | id (PK)            |             | id (PK)            |             | id (PK)            |     |
|  | name               |             | worker_id (FK)     |             | tunnel             |     |
|  | zone, tunnel       |             | ch4, co, o2, temp  |             | x, y, depth, rssi  |     |
|  | x, y, depth        |             | heart_rate, battery|             | status, last_seen  |     |
|  | ch4, co, o2, temp  |             | created_at         |             +--------------------+     |
|  | status, risk       |             +--------------------+                                        |
|  | helmet_status      |                                                                           |
|  | wristband_status   |             +--------------------+             +--------------------+     |
|  +--------------------+ 1         * |       alerts       |             |     geofences      |     |
|          | 1                        +--------------------+             +--------------------+     |
|          |                          | id (PK)            |             | id (PK)            |     |
|          v *                        | worker_id (FK)     |             | name, zone, type   |     |

|  |      devices       |             | created_at         |             | active             |     |
```

### Table Specifications

#### 1. `workers` (Core State Table)
Maintains current real-time state for every active subterranean worker.

```sql
CREATE TABLE IF NOT EXISTS workers (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  zone TEXT DEFAULT 'Zone A',
  tunnel TEXT DEFAULT 'T1',
  shift TEXT DEFAULT 'A',
  x REAL DEFAULT 0,
  y REAL DEFAULT 0,
  depth REAL DEFAULT 0,
  ch4 REAL DEFAULT 0,
  co REAL DEFAULT 0,
  flammable_gas REAL DEFAULT 0,
  o2 REAL DEFAULT 20.9,
  temp REAL DEFAULT 22,
  heart_rate INTEGER DEFAULT 72,
  battery INTEGER DEFAULT 100,
  wristband_battery INTEGER DEFAULT 100,
  helmet_status TEXT DEFAULT 'offline',
  wristband_status TEXT DEFAULT 'offline',
  panic INTEGER DEFAULT 0,
  fall INTEGER DEFAULT 0,
  motion INTEGER DEFAULT 1,
  rssi INTEGER DEFAULT -80,
  risk REAL DEFAULT 0,
  status TEXT DEFAULT 'online',
  last_seen TEXT,
  protocol TEXT DEFAULT 'LoRaWAN',
  lat REAL DEFAULT 0,
  lng REAL DEFAULT 0
);
```
- **Operational Nuance**: `status` column represents composite operational status: `'online'`, `'warning'`, `'critical'`, `'emergency'`, `'degraded_mode'`, or `'offline'`.

---

#### 2. `telemetry` (Append-Only Time-Series Log)
Maintains immutable historical sensor records for auditing, regulatory compliance, and time-series charting.

```sql
CREATE TABLE IF NOT EXISTS telemetry (
  id TEXT PRIMARY KEY,
  worker_id TEXT,
  zone TEXT,
  tunnel TEXT,
  x REAL,
  y REAL,
  depth REAL,
  ch4 REAL,
  co REAL,
  flammable_gas REAL,
  o2 REAL,
  temp REAL,
  heart_rate INTEGER,
  battery INTEGER,
  panic INTEGER,
  fall INTEGER,
  rssi INTEGER,
  risk REAL,
  created_at TEXT
);
```

---

#### 3. `alerts` (Safety Violations & Alarms)

```sql
CREATE TABLE IF NOT EXISTS alerts (
  id TEXT PRIMARY KEY,
  level TEXT NOT NULL,       -- 'warning' | 'critical' | 'emergency' | 'info'
  title TEXT NOT NULL,
  desc TEXT,
  worker_id TEXT DEFAULT '',
  zone TEXT DEFAULT '',
  type TEXT DEFAULT '',      -- 'SENSOR_FAILURE' | 'MANUAL_SOS' | 'DEVICE_OFFLINE' | ''
  priority TEXT DEFAULT 'warning',
  created_at TEXT
);
```

---

#### 4. `sensor_faults` (Maintenance & Calibration Tracking)
Tracks faulty, flatlined, or disconnected sensors over time for maintenance planning.

```sql
CREATE TABLE IF NOT EXISTS sensor_faults (
  id TEXT PRIMARY KEY,       -- Formatted: SFAULT::{worker_id}::{sensorKey}
  worker_id TEXT NOT NULL,
  sensor TEXT NOT NULL,      -- 'ch4' | 'temp' | 'telemetry' | 'o2'
  severity TEXT NOT NULL,    -- 'warning' | 'critical'
  first_detected_at TEXT,
  last_detected_at TEXT,
  last_active_at TEXT,
  repair_status TEXT DEFAULT 'required', -- 'required' | 'in_progress' | 'resolved'
  notes TEXT DEFAULT '',
  updated_at TEXT
);
```

---

#### 5. Additional Relational Tables
- **`devices`**: Tracks individual hardware unit health (`id TEXT PRIMARY KEY`, `worker_id`, `type` (`"helmet"` | `"wristband"`), `battery`, `status`, `last_seen`).
- **`anchors`**: Repeater beacon nodes (`id`, `tunnel`, `x`, `y`, `depth`, `rssi`, `status`, `last_seen`).
- **`geofences`**: Spatial hazard boundaries (`id`, `name`, `zone`, `type` (`"hazard"`, `"machinery"`, `"restricted"`, `"safe"`), `radius`, `cx`, `cy`, `active`).
- **`refuges`**: Underground life-support chambers (`id`, `name`, `zone`, `tunnel`, `x`, `y`, `capacity`, `supplies`, `status`).
- **`incidents`**: Manual supervisor safety reports (`id`, `type`, `description`, `zone`, `severity`, `reporter`, `status`, `created_at`).
- **`evacuations`**: Log of evacuation orders (`id`, `zone`, `reason`, `initiated_by`, `status`, `created_at`).
- **`drones`**: Autonomous inspection units (`id`, `name`, `zone`, `status`, `battery`, `feed`, `lastInspection`).
- **`settings`**: Key-value JSON storage for site coordinates and alarm limits (`key TEXT PRIMARY KEY`, `value TEXT`).
- **`users`**: Operator authentication accounts (`id`, `email UNIQUE`, `password_hash`, `name`, `role`, `created_at`).

## 4. Indexing Audit & Query Performance Analysis

### Current Indexing State
**Critical Audit Finding**: The SQLite database currently contains **zero explicit secondary indexes** beyond the implicit B-tree indexes generated on `PRIMARY KEY` columns (`id`).

### Performance Bottlenecks in Production Queries:
1. **Time-Series Querying (`GET /api/telemetry`)**:
   ```sql
   SELECT * FROM telemetry 
   WHERE created_at > datetime('now', '-24 hours') AND worker_id = 'MNR-001'
   ORDER BY created_at DESC LIMIT 500;
   ```
   *Execution Cost*: Without secondary indexes on `created_at` or `worker_id`, this query performs a **Full Table Scan ($O(N)$)** across hundreds of thousands of rows.
2. **Alert Filtering (`GET /api/alerts`)**:
   ```sql
   SELECT * FROM alerts WHERE level = 'critical' ORDER BY created_at DESC;
   ```
   *Execution Cost*: Full table scan.

### Recommended Production Index Definitions:
```sql
CREATE INDEX idx_telemetry_worker_created ON telemetry (worker_id, created_at DESC);
CREATE INDEX idx_telemetry_created ON telemetry (created_at DESC);
CREATE INDEX idx_alerts_level_created ON alerts (level, created_at DESC);
CREATE INDEX idx_sensor_faults_unresolved ON sensor_faults (repair_status, last_detected_at DESC);
CREATE INDEX idx_workers_risk ON workers (risk DESC);
```

## 6. Complete WebSocket Event Catalog

All real-time messages adhere to standard envelope: `{ type: STRING, payload: OBJECT, ts: TIMESTAMP }`.

| Event Type Name | Direction | Payload Structure | Triggering Event in System |
| :--- | :--- | :--- | :--- |
| `SNAPSHOT` | Server $\to$ Client | `{ workers: [...] }` | Initial client connection handshake |
| `WORKER_UPDATE` | Server $\to$ Client | Complete worker object | Inbound telemetry processed / clamped |
| `NEW_ALERT` | Server $\to$ Client | `{ id, level, title, desc, worker_id, zone }`| Threshold breached or sensor fusion fired |
| `ANCHOR_UPDATE` | Server $\to$ Client | `{ id, tunnel, x, y, rssi, status }` | Repeater heartbeat received (15s cadence) |
| `DEVICE_STATUS_UPDATE`| Server $\to$ Client | `{ deviceId, type, status, last_seen }` | Helmet or wristband transitions online/offline |
| `WRISTBAND_UPDATE` | Server $\to$ Client | `{ workerId, battery, movement, sos, signal }` | Fallback wristband telemetry packet arrives |
| `ESCALATION_STAGE` | Server $\to$ Client | `{ workerId, workerName, stage, countdown, zone }`| Alert escalation timer ticks ($10\text{s}$, $20\text{s}$, $0\text{s}$) |
| `ESCALATION_CANCELLED`| Server $\to$ Client | `{ workerId }` | Worker risk drops below 3; escalation cleared |
| `OPTIMIZATION_UPDATE`| Server $\to$ Client | `{ safetyScore, globalRisk, actionItems, ... }` | Background optimizer loop finishes run (30s) |
| `EVACUATION_ORDERED`| Server $\to$ Client | `{ id, zone, reason }` | Zone evacuation ordered by operator |
| `BROADCAST_MESSAGE` | Server $\to$ Client | `{ zone, message, level, title, ts }` | Public announcement broadcast to mine |
| `CONTACT_LOG_UPDATE` | Server $\to$ Client | `{ type, to, message, status, sid }` | Twilio SMS or voice call dispatched |
| `GEOFENCE_ADDED` | Server $\to$ Client | Geofence record object | New spatial geofence created |
| `DRONE_DEPLOYED` | Server $\to$ Client | Drone record object | Drone dispatched to tunnel drift |
